# 测试计划

## 1. 测试环境

| 项目 | 配置 |
|---|---|
| 从站 | STM32F103C8T6 + 3.3V MAX3485/SP3485 模块 |
| 网关 | STM32F407 探索者 V3，FreeRTOS |
| 总线 | RS485，115200 8N1，双绞线，两端 120Ω |
| PC 工具 | USB-RS485、USB-TTL、逻辑分析仪 |
| Linux | Linux VM 或物理机，C + epoll + SQLite |
| 故障注入 | F103 寄存器注入 + Python 模拟器 |

## 2. Modbus RTU

| 编号 | 场景 | 预期 |
|---|---|---|
| MB-01 | 0x03 正常读 | 返回正确保持寄存器 |
| MB-02 | 0x04 正常读 | 返回正确输入寄存器 |
| MB-03 | 0x06 写单寄存器 | 写入并回显 |
| MB-04 | 0x10 写多寄存器 | 批量写入成功 |
| MB-05 | CRC 错误 | 丢弃并计数 |
| MB-06 | 非法功能码 | 异常码 0x01 |
| MB-07 | 非法地址 | 异常码 0x02 |
| MB-08 | 非法数据值 | 异常码 0x03 |
| MB-09 | 响应超时 | 重试后失败 |
| MB-10 | 连续失败 | 离线降频 |
| MB-11 | 设备恢复 | 连续成功后上线 |
| MB-12 | 广播写 0x06 | 从站执行、不响应 |
| MB-13 | 0x10 数量超限 | 异常码 0x03 |
| MB-14 | 0x03 读输入区地址 | 异常码 0x02 |
| MB-15 | 故障注入超时 | 30 秒后自动恢复 |

## 3. 主站与调度器

| 编号 | 场景 | 预期 |
|---|---|---|
| MS-01 | 单从站读写 | 0x03/0x04/0x06/0x10 正常 |
| MS-02 | 响应超时 | 重试，计数正确 |
| MS-03 | 重试不阻塞 | 重试放回队尾，其他从站继续 |
| MS-04 | 连续失败 | 3 次后离线，轮询降频 |
| MS-05 | 设备恢复 | 连续成功 2 次后上线 |
| MS-06 | 写优先 | 写请求先于普通采集 |
| MS-07 | 队列满 | 计数并记录，不阻塞生产者 |

## 4. 应用层协议与 TCP

| 编号 | 场景 | 预期 |
|---|---|---|
| APP-01 | 一帧拆多次发送 | 服务正确拼接 |
| APP-02 | 多帧合并一次发送 | 服务循环解析 |
| APP-03 | 错误 magic | 断开并记录 |
| APP-04 | header CRC 错 | 断开并记录 |
| APP-05 | payload CRC 错 | 丢弃并记录 |
| APP-06 | payload 长度超限 | 断开并记录 |
| APP-07 | 重复 sequence | 计数并丢弃 |
| APP-08 | 不支持的 version | 断开并记录 |
| APP-09 | 发送一半断开 | 清理连接，无内存泄漏 |
| APP-10 | 心跳超时 | 标记离线并清理会话 |

## 5. Linux 服务

| 编号 | 场景 | 预期 |
|---|---|---|
| LNX-01 | 多客户端并发 | 稳定接收、解析、入库 |
| LNX-02 | 批量写入 | 500ms–1s 批量提交 |
| LNX-03 | 服务重启 | 网关重连后恢复 |
| LNX-04 | SQLite 写入失败 | 记录错误并重试，不阻塞网络 |
| LNX-05 | 24 小时 ASan | 无内存错误、无崩溃 |
| LNX-06 | 保留期清理 | 按天清理，数据库大小可控 |

## 6. 稳定性

| 编号 | 配置 | 指标 |
|---|---|---|
| STB-01 | 4 个逻辑从站、50 个采集点（F103 实表 18 点，压力测试由模拟器补齐）、最短周期 200ms、连续 24h | 无死锁、无看门狗复位、ASan 无错误 |

记录项：

- 轮询成功率
- 事务延迟 P50/P95
- 重试次数、离线次数、恢复次数
- 任务栈 high water mark
- 队列占用峰值
- 数据库行数/天、数据库大小、WAL 大小
- 单设备离线时其他设备是否正常

## 7. 报告规则

- 每个阶段完成后追加实测结果，不提前写“已通过”。
- 测试报告包含环境、步骤、原始日志位置、指标和结论。
- 失败用例保留复现步骤，不删除。
- 对外文档只使用实测数字。
